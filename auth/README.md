# Auth Service

Сервис **Auth** отвечает за аутентификацию и управление пользователями в микросервисной системе интернет-магазина.

Он предоставляет HTTP API для регистрации и авторизации пользователей, выпускает JWT-токены, управляет пользовательскими данными и взаимодействует с другими сервисами системы.

После успешной регистрации сервис публикует события через RabbitMQ, позволяя другим сервисам асинхронно выполнять необходимые действия.

---

# Назначение сервиса

Сервис отвечает за следующие задачи:

* регистрация пользователей;
* авторизация пользователей;
* выпуск JWT-токенов;
* проверка данных пользователя;
* управление учетными записями;
* публикация событий после регистрации;
* централизованная обработка ошибок;
* сбор метрик Prometheus.

---

# Архитектура

Сервис построен по слоистой архитектуре.

```text
HTTP API
     │
     ▼

     │

     │
     ▼
Repository
```

После успешной регистрации сервис публикует событие в RabbitMQ.

---

# Основные компоненты

## HTTP API

Предоставляет API для работы с пользователями.

Основные операции:

* регистрация пользователя;
* авторизация;
* получение информации о пользователе;
* проверка токена.

---

## Auth Service

Отвечает за процессы аутентификации.

Основные задачи:

* проверка учетных данных;
* генерация JWT;
* проверка срока действия токена;
* выдача access token.

---

## Users Service

Отвечает за управление пользователями.

Основные задачи:

* создание пользователей;
* получение информации о пользователях;
* валидация пользовательских данных.

---

## Repository Layer

Отвечает за работу с PostgreSQL.

Используется для:

* хранения пользователей;
* хранения учетных данных;
* поиска пользователей.

---

## RabbitMQ Producer

После регистрации нового пользователя сервис публикует событие.

Другие сервисы могут подписаться на очередь и выполнить собственную обработку, например:

* создание профиля;
* отправку приветственного письма;
* инициализацию пользовательских данных.

---

# Безопасность

Сервис реализует основные механизмы безопасности:

* хранение паролей в виде хэшей;
* выпуск JWT-токенов;
* проверку срока действия токена;
* валидацию входных данных;
* централизованную обработку ошибок.

---

# Хранение данных

## PostgreSQL

Используется как основное постоянное хранилище.

Хранятся:

* пользователи;
* учетные данные;
* служебная информация.

# Взаимодействие с другими сервисами

После успешной регистрации:

```text
Client
    │
    ▼
Auth Service
    │
    ▼
RabbitMQ
    │
    ▼
Другие сервисы
```

JWT-токены используются Gateway для проверки авторизации пользователя.

# Мониторинг

Сервис поддерживает централизованный мониторинг.

Используются:

* Prometheus;
* Zap.

Собираются:

* количество запросов;
* время обработки;
* ошибки авторизации;
* ошибки работы с БД.

# Основные архитектурные решения

* сервис разделён на подсистемы аутентификации и управления пользователями;
* JWT используется для авторизации клиентов;
* пароли хранятся только в виде хэшей;
* RabbitMQ применяется для публикации событий после регистрации;
* сервис построен по слоистой архитектуре;
* бизнес-логика полностью отделена от транспортного слоя и слоя доступа к данным.
