# Сервисы проекта

Проект построен по микросервисной архитектуре.

Каждый сервис отвечает за ограниченную область ответственности и взаимодействует с другими сервисами через gRPC или брокер сообщений.

# Gateway Service

## Назначение

Единая точка входа в систему.

Принимает HTTP-запросы клиентов, выполняет предварительную обработку и маршрутизирует их во внутренние сервисы по gRPC.

---

## Основные обязанности

* маршрутизация запросов;
* проверка JWT;
* применение middleware;
* централизованное логирование;
* ограничение количества запросов;
* сбор метрик Prometheus;
* предоставление Swagger-документации.

---

## Взаимодействие

Работает с:

* Auth Service
* Cart Service
* Products Service

# Auth Service

## Назначение

Отвечает за регистрацию, авторизацию пользователей и выпуск JWT-токенов.

После регистрации публикует событие в брокер сообщений.

---

## Основные обязанности

* регистрация пользователей;
* авторизация;
* выпуск JWT;
* хранение пользователей;
* публикация событий.

---

## Используемые технологии

* PostgreSQL
* RabbitMQ
* JWT


# Products Service

## Назначение

Является владельцем данных о товарах.

Предоставляет HTTP и gRPC API для получения информации о товарах и публикует события при изменении каталога.

---

## Основные обязанности

* хранение товаров;
* получение карточек товаров;
* кэширование;
* публикация событий в Kafka.

---

## Используемые технологии

* PostgreSQL
* Redis
* Kafka
* gRPC

# Cart Service

## Назначение

Отвечает за управление корзинами пользователей.

Хранит только идентификаторы товаров и их количество.

Для получения актуальной информации о товарах использует Product Service.

---

## Основные обязанности

* управление корзиной;
* кэширование корзин;
* получение информации о товарах;
* инвалидация кэша.

---

## Используемые технологии

* PostgreSQL
* Redis
* Kafka
* gRPC

# Принципы взаимодействия сервисов

В проекте используются следующие способы взаимодействия.

## HTTP

Используется только для взаимодействия клиентов с Gateway.

---

## gRPC

Используется для синхронного взаимодействия между внутренними сервисами.

Примеры:

* Gateway → Auth
* Gateway → Products
* Gateway → Cart
* Cart → Products

---

## Брокер сообщений

Используется для асинхронного взаимодействия.

Примеры:

* регистрация пользователя;
* публикация изменений товаров;
* инвалидация кэша.
