# Gateway Service

Сервис **Gateway** является единой точкой входа в микросервисную систему интернет-магазина.

Он принимает HTTP-запросы от клиентов, выполняет предварительную обработку, проверяет авторизацию пользователя, применяет middleware и маршрутизирует запросы в соответствующие внутренние сервисы по gRPC.

Gateway скрывает внутреннюю архитектуру системы от клиента и предоставляет единый HTTP API.

---

# Назначение сервиса

Сервис отвечает за следующие задачи:

* приём HTTP-запросов от клиентов;
* маршрутизацию запросов во внутренние сервисы;
* проверку JWT-токенов;
* регистрацию и авторизацию пользователей;
* применение middleware;
* централизованное логирование запросов;
* сбор метрик Prometheus;
* предоставление Swagger-документации.

---

# Архитектура

Gateway является входной точкой системы.

```text
                    Client
                       │
                       ▼
                HTTP Gateway
                       │
      ┌────────────────┼────────────────┐
      ▼                ▼                ▼
   Auth Service    Cart Service    Products Service
       gRPC            gRPC              gRPC
```

Внутреннее взаимодействие между сервисами выполняется по gRPC.

---

# Основные компоненты

## HTTP Server

Предоставляет единый HTTP API для клиентов.

Основные группы маршрутов:

* аутентификация;
* работа с корзиной;
* работа с товарами;
* Swagger;
* метрики Prometheus.

---

## Middleware

Перед обработкой каждый запрос проходит цепочку middleware.

Используются:

* Request ID;
* Recovery;
* Logger;
* CORS;
* JWT Authentication;
* Rate Limiter;
* Prometheus Metrics.

Такой подход позволяет централизованно реализовать общие механизмы обработки запросов.

---

## Auth Middleware

Защищённые маршруты требуют наличия корректного JWT.

Middleware:

* извлекает токен;
* проверяет его валидность;
* получает информацию о пользователе;
* передаёт управление обработчику.

---

## gRPC Clients

Gateway не содержит собственной бизнес-логики.

После обработки HTTP-запроса он обращается к соответствующему внутреннему сервису через gRPC.

Используются клиенты:

* Auth Service;
* Cart Service;
* Products Service.

---

# Взаимодействие с сервисами

Gateway взаимодействует со следующими сервисами:

```text
Client
    │
    ▼
Gateway
    ├────► Auth Service
    ├────► Cart Service
    └────► Products Service
```

Внутренние сервисы недоступны напрямую извне.

Все внешние запросы проходят через Gateway.

---

# Безопасность

Gateway реализует базовые механизмы защиты API:

* проверка JWT;
* ограничение количества запросов (Rate Limiter);
* централизованная обработка ошибок;
* CORS;
* восстановление после panic (Recovery Middleware).

---

# Мониторинг

Сервис поддерживает централизованный сбор метрик.

Используются:

* Prometheus;
* Zap.

Собираются:

* количество HTTP-запросов;
* время обработки запросов;
* успешные и неуспешные операции авторизации;
* ошибки валидации запросов.

Метрики доступны по адресу:

```text
/metrics
```

---

# Swagger

Gateway предоставляет Swagger-документацию для HTTP API.

После запуска документация доступна по адресу:

```text
/api/gateway/swagger/index.html
```

# Основные архитектурные решения

* Gateway является единой точкой входа в систему.
* Вся бизнес-логика находится во внутренних сервисах.
* Gateway отвечает только за обработку HTTP-запросов, применение middleware и маршрутизацию.
* Внутреннее взаимодействие выполняется через gRPC.
* Все общие механизмы (логирование, авторизация, мониторинг, обработка ошибок) реализованы централизованно.
* Swagger используется для документирования HTTP API.
