# Users Service

Сервис **Users** планировался как отдельный сервис для хранения и предоставления пользовательского профиля.

В текущей версии проекта сервис не реализован как отдельное приложение. Его роль частично закрывает Auth Service, который отвечает за регистрацию, авторизацию и хранение базовой информации о пользователях.

---

# Планируемое назначение сервиса

Users Service должен был отвечать за:

* хранение пользовательских профилей;
* получение информации о пользователе;
* обновление данных профиля;
* хранение служебной пользовательской информации;
* обработку событий регистрации пользователей;
* предоставление пользовательских данных другим сервисам.

---

# Предполагаемый сценарий работы

После регистрации пользователя Auth Service должен публиковать событие в брокер сообщений.

```text
Auth Service
     │
     ▼
RabbitMQ / Kafka
     │
     ▼
Users Service
     │
     ▼
PostgreSQL
```

Users Service должен был получать событие о новом пользователе, создавать запись в собственной базе данных и дальше выступать владельцем данных пользовательского профиля.

---

# Почему сервис не был реализован

На текущем этапе проекта Users Service не был выделен в отдельный сервис, так как основная цель проекта заключалась в проработке ключевых частей микросервисной архитектуры:

* Gateway как единая точка входа;
* Auth Service для регистрации и авторизации;
* Products Service как владелец товарных данных;
* Cart Service как сервис корзины;
* gRPC-взаимодействие между сервисами;
* Redis-кэширование;
* Kafka/RabbitMQ для асинхронного взаимодействия.

Реализация Users Service была отложена, так как его базовая логика повторяла уже реализованные подходы: consumer брокера, запись в PostgreSQL и предоставление API для чтения данных.

---

# Что планировалось реализовать

Возможная структура сервиса:

```text
cmd/
    server/

internal/
    handler/
    service/
    repository/
    broker/
    config/
    db/
    logger/
    metrics/
    model/
```

Основные компоненты:

* RabbitMQ/Kafka consumer для обработки события регистрации;
* PostgreSQL repository для хранения профилей;
* gRPC API для получения профиля пользователя;
* HTTP API для обновления профиля;
* Prometheus-метрики;
* структурированное логирование через Zap.
